# あそびひろば (SagashimonoGame)

子ども向けのミニゲームを集めたアプリです。起動するとホーム画面でゲームを選べます。

- 最初に「なまえ」と「なんさい？」を登録します（端末に保存。兄弟で分けられ、進捗はプロフィールごと）。年齢に合わせて難易度とクイズのレベルが変わります
- ホーム画面右上の ⚙️ から「おうちのひと設定」（かけ算の関門あり）。べんきょうクイズを出す場面・レベル・科目や、ネジはずしのおたすけ回数を決められます
- オフラインでも動きます（PWA）

| ゲーム | 内容 | 状態 |
|---|---|---|
| 🔍 さがしものゲーム | 「ミッケ」風のもの探しゲーム | 公開中 |
| 🔩 ネジはずし | 3D の図形に刺さった色付きネジを外して同じ色のボックスに集めるパズル | 公開中（[計画書](docs/ネジはずしゲーム計画.md)） |
| 💄 マジックメイクミラー | インカメラに映した顔に、顔認識でおけしょうを重ねたり、塗る場所と向きを矢印で案内したりする鏡 | 試作中（[計画書](docs/お化粧アプリ計画.md)） |

URL: https://kake-git-hub.github.io/SagashimonoGame/

## 技術スタック

- React 19 + TypeScript
- Vite
- three.js + @react-three/fiber + @react-three/drei（ネジはずしの 3D 表示）
- MediaPipe Face Landmarker（`@mediapipe/tasks-vision`。マジックメイクミラーの顔認識。端末内で動き、映像は外に出ない）
- canvas-confetti（紙吹雪演出）
- vitest（ロジックの単体テストとステージ検証）
- PWA（vite-plugin-pwa + Workbox。オフライン起動と自動アップデート）

## 開発

```bash

# ヘッドレスブラウザで実際に遊んで確認（scripts/e2e/README.md）
```

## 🔍 さがしものゲーム

### 機能

- 画像内の隠されたアイテムを探すゲーム
- タブレット横画面・スマホ縦画面に対応
- ヒント機能（未発見アイテムの位置を光らせる）
- 進捗保存（中断再開対応）
- クリア時の紙吹雪演出
- パズルエディタ（新しいパズルを作成可能）
- お題リストのテキスト/サムネイル切替

### パズルデータの追加方法

1. `public/puzzles/images/` に画像を追加
2. `public/puzzles/` にパズル定義JSONを作成
3. `public/puzzles/index.json` にパズル情報を追加

#### パズルJSONフォーマット

```json
{
  "id": "puzzle-id",
  "name": "パズル名",
  "imageSrc": "puzzles/images/puzzle-id.webp",
  "targets": [
    {"title": "アイテム名", "position": [x, y]}
  ]
}
```

座標は画像の左上を(0,0)、右下を(1000,1000)としたスケールです。

#### AI生成画像の活用

AI画像生成ツールで画像とお題リストを同時に生成できます。生成されたJSONをエディタでインポート可能です。

## 🔩 ネジはずし

3D の図形に刺さった色付きネジをタップして外し、同じ色のボックス（3 本入り）に集めるパズルです。
仕様と実装計画は [docs/ネジはずしゲーム計画.md](docs/ネジはずしゲーム計画.md) を参照してください。

### あそびかた

- ドラッグで図形を回す。2 本指で拡大縮小。何もない所をすばやく 2 回タップ（または ↺）で向きを戻す
- ネジをタップすると外れて、同じ色のボックスへ飛ぶ。ボックスが満杯になると次のボックスが来る
- 同じ色のボックスが無いときは「おきば」に置かれる。おきばが満杯になると失敗
- 板の下や、ほかのネジの軸の下にあるネジは、上の物を先に外さないと外せない（震えて、邪魔している物が赤く光る）
- ネジが全部外れたパーツは落ちる（かけらが飛び散る）。全部のネジを外すとクリア。底にもネジがあるので、ひっくり返して探す
- 画面は 3D が全面で、ボックスとおきばは横向きなら左右、縦向きなら上下に透過で重なる
- おたすけ: 「＋はこ」でボックスの枠を、「＋おきば」でおきばの穴を増やせる。失敗したら「つづきから」で 3 手前に戻れる。おうちのひと設定でクイズをオンにすると、これらの前にべんきょうクイズが出る（つぎのステージへ進むときも）
- 発掘ステージ（💖 ハート・⭐ ほし・💎 ダイヤ・🦕 きょうりゅうのかせき・🥚 たまご・👑 おうかん・💍 ゆびわ・🪙 きんか・🐚 アンモナイト）: 土のブロックを全部外すと中からたからものが出てきて、じっくり眺めてから「たからばこ」に入る。ふたの上の石、板を分けたふた、底の受け皿など、覆いが何層にもなっている
- 展開図ステージ（🎲 さいころ・⬡ ろっかくのはこ）: 面のネジを外すと落ちずにパタンと開いて展開図になる
- 外側から順に外すステージ（🎂 ケーキ・🏠 まるたのいえ・🎁 はこのなかのはこ）: 台の下のネジ、別のネジの頭にふさがれたネジ、3 層のふた など、順番を考えないと届かないネジが多い
- 🔺 ピラミッドは上の段から、かんじ「木」「田」は手前の画から外さないと下のネジが取れない
- 層を重ねたお題（🦋 ちょうちょ・✈️ ひこうき・🚢 ふね・🚂 きしゃ・🐻 くま・🕰️ とけい・🐟 さかな）: はねの上のもよう、つばさの下、車輪をつなぐ棒、時計の針と文字盤など、上の板を外すと下のネジが現れる
- ネジの色は同じ色が隣り合わないように混ぜてあり、ボックスの色の順番を考えずに手当たりしだいに外すと、むずかしいステージほどおきばがあふれやすい

### ステージの追加方法

1. `public/neji/stages/<id>.json` を作成
2. `public/neji/index.json` に `{ "id", "name", "emoji", "difficulty", "screwCount" }` を追加
3. `npm run validate:neji` で検証（物理的な重なり・色の本数・解けるか）

形だけ決めて色は自動で混ぜたいときは、`scripts/neji/stages.ts` にステージを足して `npm run gen:neji` を実行する（`scripts/neji/README.md`）。
JSON を手で書くときも `npm run gen:neji` を通すと、同じ色が隣り合わないように色とボックスの順番を決め直してくれる。

#### ステージJSONフォーマット

```json
{
  "id": "stage-01",
  "name": "はこ",
  "emoji": "📦",
  "difficulty": 1,
  "boxCapacity": 3,
  "visibleBoxes": 2,
  "bufferSlots": 5,
  "boxes": ["red", "blue"],
  "parts": [
    { "id": "base", "shape": "box", "size": [4, 1.2, 4], "position": [0, 0, 0], "color": "#8ecae6", "fixed": true }
  ],
  "screws": [
    { "id": "t1", "color": "red", "position": [1.2, 0.6, 1.2], "dir": [0, 1, 0], "length": 1.0, "partIds": ["base"] }
  ]
}
```

- 座標は右手系で Y が上。1 単位 ≒ ネジ 1 本分の長さ
- `parts[].shape`: `box`（`size`）/ `cylinder`（`radius`, `height`、ローカル Y 軸方向）/ `sphere`（`radius`）/ 飾りの `star` `heart` `gem` `bone` `egg` `ring` `crown` `shell`（`radius`, `height`。当たり判定は円柱で近似）。`rotation` はオイラー角（度）
- `treasure`: `{ "id", "name", "emoji", "partIds" }` を付けると発掘ステージ。`partIds` のパーツは `fixed: true` にする。`index.json` にも `treasure: { id, name, emoji }` を書く
- `parts[].fixed`: true なら最後まで落ちない土台。false のパーツはどれかのネジで固定されている必要がある
- `parts[].unfold`: `[{ "point", "axis", "angle" }]` を付けると落ちる代わりにちょうつがいで開く（展開図）。`cylinder` の `segments: 6` で六角柱
- `screws[].position`: 頭が乗っている面上の点。`dir` は外向き。`length` は面から内部へ入る軸の長さ（省略時 1.0）
- `screws[].partIds`: そのネジが固定しているパーツ。先頭は頭が乗っているパーツ。軸が貫くパーツはすべて列挙する
- `boxes`: ボックスが登場する順番。各色のネジ本数は `boxCapacity × その色のボックス数` と一致させる
- 色は `red / blue / green / yellow / purple / orange`
- ネジの軸同士が交差したり、頭が他のパーツに食い込んだりしていると検証でエラーになる

## 💄 マジックメイクミラー

インカメラに映した自分の顔に、顔認識（MediaPipe Face Landmarker、478 点）をもとにおけしょうを重ねたり、どこにどう塗るかを案内したりする「かしこい鏡」です。本来は単体のアプリにしたいものを、あそびひろばの中で試作しています（[計画書](docs/お化粧アプリ計画.md)、[開発ガイド](docs/お化粧アプリ開発ガイド.md)）。

### あそびかた

1. ホームで「マジックメイクミラー」を選び、「カメラを つかう」を押してカメラを許可します（カメラが使えないときや PC では「しゃしんで ためす」で写真を選べます）
2. はじめて開くときは顔を見つけるためのデータ（約 19MB）をダウンロードします。2 回目からはオフラインでも動きます
3. 画面の上の状態欄が「かおが みえているよ」になったら、下のタブで 3 つの使い方を選びます
   - **ためす**: パーツ（リップ・チーク・アイシャドウ・アイライン・まゆ・ハイライト・ベース・コンシーラー）→ 色 → つよさ を選ぶと、顔に重ねて表示されます。「くらべる」を押している間は元の顔、「ほぞん」で写真に残せます（共有シート / ダウンロード）
   - **おしえて**: 手順（ナチュラル / おでかけ / リップだけ / チークだけ）を選ぶと、ステップごとに塗る場所が光り、塗る向きが矢印で流れます。顔が動いても追従します。チークでは「にっこり」すると位置が決まります。「できあがりを みる」で完成形を重ねられます
   - **ていあん**: 「しんだん する」で顔のかたち・めのかたち・はだの色みを見て、合いそうな色と手順をすすめます（あくまで目安です）
4. 右上の ⚙️ で鏡像の切り替え、顔の点の表示、速さの表示、GPU / CPU の切り替えができます

うつした顔はこの端末の中だけで使い、どこにも送りません。「ほぞん」を押したときだけ写真として書き出します。

### 色と手順の追加方法

- 色: `public/makeup/palettes.json` にパーツごとの `{ "name": "コーラル", "color": "#f0806a" }` を足します
- 手順: `public/makeup/recipes/<id>.json` を作り、`public/makeup/recipes/index.json` に `{ "id", "name", "emoji", "description", "stepCount" }` を足します。`npm test` が参照切れとステップ数を検証します

#### レシピ JSON フォーマット

```json
{
  "id": "natural",
  "name": "ナチュラル",
  "emoji": "🌿",
  "description": "まいにちの かんたんメイク",
  "steps": [
    {
      "id": "blush",
      "part": "blush",
      "title": "チーク",
      "text": "にっこり すると たかくなる ところから、こめかみへ むかって ふんわり",
      "pose": "smile",
      "regions": ["cheekR", "cheekL"],
      "strokes": [{ "from": "cheekCenterR", "to": "templeR" }, { "from": "cheekCenterL", "to": "templeL" }],
      "marks": [{ "type": "dot", "anchor": "cheekCenterR" }],
      "look": { "layer": "blush", "color": "#f3a5a5", "opacity": 0.55 }
    }
  ]
}
```

- `part`: `lip` / `blush` / `eyeshadow` / `eyeliner` / `brow` / `highlight` / `base` / `concealer` / `mascara` / `finish`（絵文字と、ためす のレイヤーに対応）
- `pose`: `front`（省略時）/ `smile`（にっこり）/ `closeEyes`（目を閉じる）。できているかを表情から判定して文言を切り替えます
- `regions`: 光らせる領域の名前。`strokes`: 矢印が流れる線（`along` で既定の線をなぞる。`reverse: true` で逆向き。または `from` / `to` で点を結ぶ）。`marks`: 目印（`vline` は縦線、`dot` は点）
- 使える名前は `src/games/makeup/logic/regions.ts` の `REGION_NAMES` / `PATH_NAMES` / `POINT_NAMES`。左右は自分から見た左右（`R` が自分の右）
- `look`: 「できあがりを みる」で ためす に流し込む色

## PWA（オフライン起動と自動アップデート）

- Service Worker は `src/sw.ts`（Workbox）で、ビルド時に `dist/sw.js` と `dist/manifest.json` が生成されます。`public/` に手書きの `sw.js` や `manifest.json` は置きません（manifest の内容は `vite.config.ts` で編集）
- JS / CSS / HTML / アイコン / パズル定義 / ステージ定義 / さがしものゲームの絵（webp）はインストール時に事前キャッシュされ、一度ひらけばオフラインでも全部遊べます。絵は内容が変わらなければ新しいビルドでも再ダウンロードされません
- 例外はマジックメイクミラーの顔認識（wasm 約 14MB とモデル約 4MB）で、事前キャッシュには入れず、はじめて開いたときにダウンロードして保存します（以後はオフラインでも動きます）。他のゲームしか遊ばない端末に大きなファイルを落とさないためです
- 新しいビルドが公開されると自動で更新します（`src/services/pwaUpdateService.ts`）
  - 確認するタイミング: 起動時、アプリが前面に戻ったとき、1 時間ごと
  - 新バージョンが見つかると、ゲームの途中を邪魔しないよう **ホーム画面にいるとき** に「こうしんしています…」と表示して切り替えます（ゲーム中ならホームに戻ったときに切り替わります）
- ホーム画面の下に表示される「バージョン: 日時」はビルド日時です。実機でどのビルドが動いているか確認できます
