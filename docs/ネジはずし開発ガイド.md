# ネジはずし 開発ガイド

別セッション・別の人が改良を続けるための内部資料。遊び方とステージ JSON の形式は `README.md`、当初の計画は `docs/ネジはずしゲーム計画.md` を参照。

## 1. 全体像

```
NejiApp.tsx                  ステージ一覧 ↔ ゲーム画面の切り替え、進捗の読み書き
 ├ components/StageList.tsx  一覧（クリア済み表示）
 └ components/NejiGameScreen.tsx
     ├ hooks/useNejiGame.ts          useReducer(logic/gameReducer) のラッパー
     ├ hooks/useHudChoreography.ts   リデューサーのイベント → HUD 演出（飛ぶ・穴を埋める・箱の退場）
     ├ components/Scene.tsx          R3F Canvas。カメラ合わせ、回転・ズーム、パーツ/ネジの描画
     │   ├ PartMesh.tsx              パーツ（落下アニメ・赤表示）
     │   └ ScrewMesh.tsx             ネジ（タップ判定・取り外しアニメ・震え）
     ├ components/BoxHud.tsx / BufferHud.tsx / FlyingScrewLayer.tsx / ScrewIcon.tsx
     └ components/ResultOverlay.tsx  クリア / 失敗
logic/                        three.js の数学クラスのみ依存。Node のテストで動く
 ├ normalize.ts   既定値の補完（three に依存しない。軽い画面からはこれだけ import する）
 ├ geometry.ts    パーツ・ネジの行列、レイ交差（直方体/円柱/球/ネジ）、図形全体のバウンディング
 ├ removable.ts   「このネジは今外せるか」（レイの掃引）。邪魔している物を返す
 ├ rules.ts       落ちるパーツの判定、色仕分け（placeScrew）、ソルバー用キー
 ├ gameReducer.ts ゲーム状態の遷移。HUD 用イベントを発行
 ├ solver.ts      深さ優先探索で解けるか判定（ステージ検証・将来のヒント）
 └ validate.ts    ステージ定義の検証（物理的な重なり、色の本数、解けるか）
services/stageService.ts      public/neji/index.json とステージ JSON の取得
services/nejiStorageService.ts localStorage（neji_progress）
stages.test.ts                public/neji/stages/*.json を全部検証（npm run validate:neji）
```

依存の向き: `components → hooks → logic`。`logic` から React や WebGL に依存しない。

## 2. 1 タップの流れ

1. `ScrewMesh` が pointerdown/up の移動量と時間でタップと判定し `onTap(id)`（一番手前のネジだけ。`stopPropagation` 済み）
2. `gameReducer` の `tapScrew`:
   - `findBlockers` で邪魔物があれば `feedback`（連番付き）を更新して終了 → `ScrewMesh` が震え、`Scene` が邪魔物を赤くする
   - 外せるなら `remainingScrews` から除き `removingScrews`（表示用）へ。`findFreeParts` でネジが無くなったパーツを `fallingParts` へ
   - `placeScrew` で行き先（同色ボックス → 一時置き場 → あふれ=失敗）を決め、`events` に `screwPlaced` / `boxFull` / `boxArrived` / `bufferMoved` / `overflow` を積む
   - `status` を `playing | cleared | failed` に更新
3. `ScrewMesh` が取り外しアニメ完了時に頭の画面座標を `onRemoveDone` で返す → `NejiGameScreen` がキャンバス座標を画面座標に直して `useHudChoreography.onScrewRemoved`
4. `useHudChoreography` が飛ぶ演出（`FlyingScrewLayer`）を開始。届くまで行き先の穴は `hidden` に入れて空のまま表示。満杯ボックスは飛んでくるネジが全部届いてから `departing` にして退場アニメ
5. `status` が変わると `NejiGameScreen` が演出時間を待って `ResultOverlay` を出す

ポイント: **論理状態（リデューサー）は即時に確定し、見た目だけが遅れて追いつく**。失敗判定やクリア判定を演出に合わせて遅らせる必要はない。

## 3. 「外せるか」の判定（`removable.ts`）

ネジは先端 → 頭の方向（`dir`）にまっすぐ抜けるとみなし、抜け道に残っている物があれば外せない。

- 軸の掃引: 先端から面まで。中心 + 周囲 6 本（半径 = 軸半径 × 0.9）
- 頭の掃引: 面から `length + 頭の高さ` まで。中心 + 周囲 6 本（半径 = 頭半径 × 0.85）
- 候補: 残っているパーツ（そのネジの `partIds` は除く）と、残っている他のネジ
- 2 段階にしているのは、隣り合う平行なネジを誤検出しないため。パラメータは `constants.ts` の `BLOCK_CHECK`

パーツは `fixed` か、どれかの残っているネジの `partIds` に入っている間は落ちない。

## 4. 色仕分け（`rules.ts` の `placeScrew`）

- 同色で空きのあるボックス → 入れる。満杯になったら `completeBox`: 退場イベント → キューの次のボックスを同じ位置に出す → 一時置き場の同色を順に移す → それで満杯ならさらに繰り返す
- 同色ボックスが無い → 一時置き場の空き穴。無ければ `overflow`（失敗）
- ソルバーも同じ関数を使うので、ルールを変えるときはここだけ変える

## 5. ステージを増やす・変える

1. `public/neji/stages/<id>.json` を書く（形式は README）。単位は 1 ≒ ネジ 1 本分。Y が上
2. `public/neji/index.json` に追加（`screwCount` はネジの本数、`difficulty` は 1〜5）
3. `npm run validate:neji`。エラー文がそのまま直し方を示す。よくあるミス:
   - 軸同士の交差: 直交するネジの深さが重なっている → `length` を短くするか位置をずらす
   - 頭と軸の重なり: 同じ軸上に並ぶネジの頭の上に別のネジの先端が来ている
   - 「partIds に無いパーツを貫いている」: 軸が通るパーツは全部 `partIds` に書く（先頭は頭が乗っているパーツ）
   - 頭がパーツに埋まっている: 覆いの下のネジは頭の高さ 0.2 以上の隙間が必要。覆いは `length + 0.2` 以内の距離に置かないとブロックにならない
   - 解けない: ボックスの順番（`boxes`）がブロックの順番と合っていない。失敗時に解の有無がログに出る
4. 難易度順に `index.json` を並べる（一覧の番号は並び順）

形状を増やしたいとき（例: 円錐・トーラス）: `types.ts` の `PartDef`、`geometry.ts` の `rayPartEntry` と `partCornerPoints`、`PartMesh.tsx` の `PartGeometry` の 3 か所。

## 6. 調整しやすい値

| 何 | 場所 |
|---|---|
| ネジの寸法、ボックス容量・表示数・一時置き場の穴数の既定値 | `constants.ts`（`SCREW`, `STAGE_DEFAULTS`） |
| 判定レイの本数・半径 | `constants.ts`（`BLOCK_CHECK`） |
| アニメーション時間 | `constants.ts`（`ANIM`） |
| ネジの色 | `constants.ts`（`SCREW_COLOR_HEX`）と `types.ts` の `SCREW_COLORS` |
| タップ判定（移動 12px・700ms）、当たり判定の大きさ（頭 × 1.25） | `ScrewMesh.tsx` |
| カメラの初期角度・距離、回転の上下限、ズーム範囲 | `Scene.tsx` の `CameraRig` |
| 画素密度の上限（`dpr={[1, 2]}`）、ライト | `Scene.tsx` |
| 赤表示の強さ | `PartMesh.tsx` / `ScrewMesh.tsx` の `emissiveIntensity` |
| HUD の見た目・アニメ | `neji.css` |

## 7. 動作確認の方法

- 単体テスト: `npm test`（geometry / removable / rules / gameReducer / solver / 全ステージ）
- 実際に遊ぶ: `bash scripts/e2e/run.sh neji-smoke`（ビルド → preview → ヘッドレス Chromium でステージ 1 をクリア、ブロック表示、色仕分けの流れを確認し、スクリーンショットを `scripts/e2e/out/` に保存）
- 全ステージの見た目: `bash scripts/e2e/run.sh stage-shots`
- デバッグ用フック: URL に `?nejidebug=1` を付けると `window.__nejiDebug` に残っているネジの画面座標（`screws`）と、当たり判定を通さずタップする `tap(id)` が公開される（`Scene.tsx` の `DebugProbe`）

## 8. 既知の制限・改良候補

実機（iPad / iPhone）での操作感は未確認の項目が残っている。ユーザーからの報告をもとに調整する。

候補（やりやすい順）:

- 赤表示の見やすさ: パーツの色によっては変化が小さい。点滅や輪郭線（drei の `Edges`）に変えると分かりやすい
- タップ判定と当たり判定の大きさの実機調整（`ScrewMesh.tsx`）
- ヒント: `solver.ts` の解の先頭 1 手を光らせる（ソルバーは既にある）
- 1 手もどす: リデューサーの履歴を持てばよい（`placeScrew` は純粋関数なので巻き戻しが容易）
- 効果音（取り外し・ボックス満杯・クリア）
- ステージの追加（手作り JSON）。覆い・ピン・色の順番の組み合わせで難しくなる
- ランダム生成: `validate.ts` + `solver.ts` が既にあるので、生成 → 検証 → 解けるものだけ採用、が組める
- アプリ内エディタ: さがしものゲームの「つくる」に相当。`validate.ts` をそのまま使える
- パーツ落下を物理エンジン（@react-three/rapier）に置き換える案は、バンドルと iPad の挙動差を考えて見送っている
