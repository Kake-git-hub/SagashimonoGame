# ネジはずしゲーム 実装計画

作成日: 2026-10-08
対象ブランチ: `claude/practical-noether-ke8i8b`

このドキュメントは、既存の「さがしものゲーム」と同じアプリ（同じリポジトリ・同じ GitHub Pages）に、
3D の図形に刺さったネジを外していくスマホゲーム風の新ゲーム「ネジはずし」を追加するための計画です。
実装に入る前の合意用ドキュメントなので、気になる点があればこのファイルにコメントするか、チャットで指摘してください。

## 1. 質疑で決まったこと

| 項目 | 決定 |
|---|---|
| 基本ルール | 色仕分けあり（Screw Sort 3D 風）。外したネジは同色ボックスへ、無ければ一時置き場へ。一時置き場が満杯で失敗 |
| 外せないネジの条件 | パーツ重なり ＋ ネジ同士の干渉（両方）。ネジの抜け道に他の物が残っていれば外せない |
| ステージの作り方 | 定義 JSON を手作り（まず 10 面程度）。エディタ・自動生成は後のフェーズ候補 |
| アプリ名 | 新しい共通名「あそびひろば」（仮）。トップ画面でゲームを選ぶ |

## 2. 参考ゲームの調査まとめ

「ネジを外す 3D パズル」ジャンル（Screw Sort 3D、ネジマッチ、3D Bolt Master、Screw Out 系）の共通ルールは次の通りです。

- 画面中央に 3D の図形（箱・板・キャラクターなど）が表示され、色付きのネジが刺さっている
- ドラッグで図形を回転、ネジをタップで外す
- 画面上部に「色ボックス」が 2〜3 個並び、各ボックスは同じ色のネジを 3 本まで受け入れる。満杯になると退場し、次のボックスが出てくる
- 対応するボックスが無い色のネジは「一時置き場」（4〜5 穴）に置かれ、後で同色ボックスが来ると自動で移動する
- 一時置き場が満杯の状態でさらに置こうとすると失敗（ゲームオーバー）
- ネジは「上に乗っている板」や「交差している別のネジ」に邪魔されていると外せない。外せないネジをタップすると震えて教えてくれる
- ネジが全部外れたパーツは落下して消える
- 全てのネジを外すとクリア

調査した主なページ:

- [Screw Sort 3D: ボルト ネジニットパズルゲーム (App Store)](https://apps.apple.com/JP/app/id6633425539)
- [3D Bolt Master: ネジパズルゲーム (App Store)](https://apps.apple.com/JP/app/id6738771575)

## 3. 仮決め事項（違っていれば指摘してください）

質疑で聞かなかった細かい点は、次の前提で進めます。すべてステージ JSON や定数で後から変更できます。

1. ボックスは 1 個 3 本入り。画面には 2 個表示し、その右に「次のボックス」の色を小さく予告表示する
2. 一時置き場は 5 穴（ステージごとに JSON で変更可）
3. 失敗条件は「一時置き場があふれる」のみ。制限時間・手数制限は無し
4. 失敗したら「ざんねん…」画面を出し、「もういちど」で同じステージを最初からやり直せる
5. ステージは最初から全て選べる（ロック無し）。クリア済みにはチェックを付け、クリア画面に「つぎのステージへ」を出す
6. 途中セーブは無し（1 ステージが短いため）。クリア済みフラグだけ保存する
7. 図形は箱・円柱・球などの基本図形を組み合わせて JSON で定義する（glTF 等のモデルファイルは使わない）
8. ゲーム名は「ネジはずし」、プラットフォーム名は「あそびひろば」
9. リポジトリ名と URL（`https://kake-git-hub.github.io/SagashimonoGame/`）は変えない。変えると GitHub Pages の URL とサービスワーカーの登録パスが変わり、インストール済みの PWA が壊れるため
10. 効果音は既存ゲームに合わせて無し（将来の拡張候補）

## 5. ネジはずしゲームの仕様

### 5.1 画面レイアウト

```
┌──────────────────────────────┐
│ ←  ステージ名      のこり 12 │  ヘッダー（既存ゲームと同じ配色）
├──────────────────────────────┤
│ [🟥🟥⬜] [🟦⬜⬜]  つぎ: 🟩  │  色ボックス（DOM）
│  ⬜ ⬜ ⬜ ⬜ ⬜               │  一時置き場（DOM）
├──────────────────────────────┤
│                              │
│         3D キャンバス        │  ドラッグで回転 / ピンチで拡大縮小 / タップでネジを外す
│                              │
└──────────────────────────────┘
```

- スマホ縦・タブレット横の両方で中央の 3D 表示が最大になるようにする（既存の `useIsTablet` を利用）
- HUD（ボックス・一時置き場）は 3D ではなく DOM で描画する。描画が軽く、タップ領域の計算も楽なため

### 5.2 操作

- 1 本指ドラッグ: 図形を回転（上下の回転は ±80° 程度に制限して裏返らないようにする）
- 2 本指ピンチ / マウスホイール: 拡大縮小（1.0〜2.5 倍に制限）。パンは無し
- タップ（移動量が小さい指の離し）: ネジを外す。ドラッグ後の指離しでは外さない
- ダブルタップ: 視点を初期位置に戻す（既存ゲームのズームリセットと同じ感覚）

### 5.3 ルール詳細

1. ネジをタップ → 外せる状態なら取り外しアニメーション（回転しながら軸方向に抜ける）→ ボックスへ飛ぶ
2. 行き先の決定
   - 表示中のボックスに同じ色で空きがある → そのボックスへ
   - 無い → 一時置き場の空き穴へ
   - 一時置き場も満杯 → 失敗（「ざんねん…」オーバーレイ）
3. ボックスが 3 本で満杯になる → 退場アニメーション → 次のボックスが登場。登場時、一時置き場に同色ネジがあれば自動でそのボックスへ移動する
4. ネジが全部外れたパーツ（`fixed` でないもの）は落下して消える
5. 残りネジが 0 になる → クリア（既存の紙吹雪演出を再利用）
6. 外せないネジをタップ → ネジを震わせ、邪魔している物を 0.5 秒ほど赤く光らせる

### 5.4 「外せるか」の判定（パーツ重なり ＋ ネジ同士の干渉）

ネジは「先端から頭の方向（軸方向）にまっすぐ抜ける」ものとして、抜け道に別の物が残っていれば外せないと判定します。

- ネジの先端から軸方向（外向き）にレイを飛ばす。中心 1 本 ＋ ネジの半径分だけずらした周囲 6 本の計 7 本で「太さのあるレイ」を近似する
- レイが当たる候補: まだ残っている全パーツ（そのネジが固定しているパーツは除く）と、そのネジ以外の残っている全ネジ
- 1 本でも何かに当たれば「外せない」。当たった物を「邪魔している物」として演出に使う
- 判定は three.js の数学クラス（Ray / Matrix4 / Box3 等）だけで行い、WebGL のシーンに依存しない純粋関数にする。これにより Node で動く検証スクリプトとゲーム本体で同じ関数を共用できる
- 形状ごとの交差計算: 直方体（パーツのローカル座標に変換して AABB 判定）、円柱（軸と側面＋両端の円盤）、球、ネジ（頭＝太く短い円柱、軸＝細い円柱）

### 5.5 パーツの落下

物理エンジンは入れません（バンドル増と iPad での挙動のばらつきを避けるため）。

- ネジが 0 本になったパーツは、JSON の `detachDir`（省略時は図形中心から外向き）に少し押し出され、その後 -Y 方向に加速しながら落ち、回転とフェードアウトを付けて 0.8 秒ほどで消える
- 落下中のパーツは判定から即座に除外する（落ち始めた瞬間に下のネジが外せるようになる）

### 5.6 演出

- 取り外し: 0.4 秒で 3 回転しながら軸方向に抜ける → 画面座標に投影して DOM のネジ画像がボックスまで放物線で飛ぶ（0.4 秒）→ ボックスの穴に収まるときに少し弾む
- ボックス満杯: 蓋が閉まって画面外へスライド、次のボックスが右からスライドイン
- クリア: 既存 `ClearOverlay` と同じ紙吹雪。「つぎのステージへ」「もういちど」「いちらんへ」
- 失敗: 暗いオーバーレイに「ざんねん…」。「もういちど」「いちらんへ」

## 6. ステージ定義 JSON

単位は「1 = ネジ 1 本分の長さ」程度のスケール。座標は右手系、Y が上。

```json
{
  "id": "stage-01",
  "name": "はこ",
  "difficulty": 1,
  "boxCapacity": 3,
  "visibleBoxes": 2,
  "bufferSlots": 5,
  "boxes": ["red", "blue", "red"],
  "parts": [
    { "id": "base",  "shape": "box", "size": [4, 1, 4], "position": [0, 0, 0], "color": "#8ecae6", "fixed": true },
    { "id": "lid",   "shape": "box", "size": [4, 0.4, 4], "position": [0, 0.7, 0], "color": "#ffb703" },
    { "id": "pole",  "shape": "cylinder", "radius": 0.3, "height": 2, "position": [1.5, 1.9, 1.5], "rotation": [0, 0, 0], "color": "#fb8500" }
  ],
  "screws": [
    { "id": "s1", "color": "red",  "position": [ 1.5, 0.9,  1.5], "dir": [0, 1, 0], "length": 1.2, "partIds": ["lid", "base"] },
    { "id": "s2", "color": "red",  "position": [-1.5, 0.9,  1.5], "dir": [0, 1, 0], "length": 1.2, "partIds": ["lid", "base"] },
    { "id": "s3", "color": "blue", "position": [ 2.0, 0.0,  0.0], "dir": [1, 0, 0], "length": 1.5, "partIds": ["base"] }
  ]
}
```

- `parts[].shape`: `box` / `cylinder` / `sphere`。`rotation` はオイラー角（度）
- `parts[].fixed`: true なら最後まで落ちない（土台）
- `screws[].position`: ネジの頭が乗っている面上の点。`dir` は外向きの単位ベクトル。`length` は面から内部へ入る軸の長さ
- `screws[].partIds`: そのネジが固定しているパーツ。先頭が頭の乗っているパーツ。これらのパーツは「外せるか」判定の対象外になる
- `boxes`: ボックスが登場する順番の色リスト。各色のネジ本数は `boxCapacity × その色のボックス数` と一致している必要がある（検証スクリプトでチェック）
- 色は `red / blue / green / yellow / purple / orange` の 6 色を既定とし、見た目の色コードは `constants.ts` で一括定義する

### 6.1 検証スクリプト（`npm run validate:neji`）

- 各色のネジ本数とボックス数の整合、`partIds` の参照切れ、ネジの頭がパーツ表面付近にあるかをチェック
- `solver.ts` で「ある順番で全部外せるか」を深さ優先探索（状態: 残りネジ集合 ＋ ボックス進行 ＋ 一時置き場の中身、訪問済み状態はメモ化）。解けないステージはエラーにする
- 解が見つかった場合はその手順を出力するので、将来のヒント機能にも流用できる
- CI（deploy.yml）のビルド前にも実行し、壊れたステージを本番に出さない

## 7. 技術選定

| ライブラリ | バージョン | 用途 |
|---|---|---|
| three | 0.186.1 | 3D 描画・数学クラス（判定ロジックでも使用） |
| @react-three/fiber | 9.8.1 | React から three を宣言的に扱う（React 19 対応） |
| @react-three/drei | 10.7.9 | OrbitControls など定番ヘルパー |
| @types/three | 0.186.0 | 型定義 |
| vitest（開発用） | 最新 | 判定ロジック・リデューサー・ソルバーの単体テスト |

- ネジはずしの画面は `React.lazy` で別チャンクに分け、さがしものゲームだけ遊ぶ場合は three を読み込まないようにする（three は gzip 後 約 150KB）
- iPad / iPhone 向けの性能対策: ポリゴン数の少ない基本図形、影は無効、`dpr` は最大 2 に制限、ライトは環境光＋平行光 1 つ
- マテリアルは `MeshStandardMaterial` のパステル配色。ネジは色付きの六角頭＋軸で、Screw Sort 3D に近い見た目にする

| three によるバンドル増で既存ゲームの初回表示が遅くなる | ネジはずしを別チャンクに遅延読み込み |
| iPad Safari で描画が重い | 低ポリゴン・影なし・dpr 上限 2・ライト 1 灯 |
| 回転ドラッグとタップの誤判定 | 指の移動量が閾値以下のときだけタップ扱い（既存ゲームの 15px 判定と同じ考え方） |
| 解けないステージを配布してしまう | ソルバー付き検証スクリプトをビルド前に実行 |
| サービスワーカーが古い画面をキャッシュ | CACHE_NAME を更新（取得はもともとネットワーク優先） |
| 既存ユーザーの進捗・自作パズルが消える | 既存の保存キーと IndexedDB 名は変更しない |

## 11. 実装メモ（計画との差分）

- ステージ検証は `scripts/validate-neji-stages.mjs` ではなく vitest のテスト `src/games/neji/stages.test.ts` として実装した（`npm run validate:neji` / `npm test`）。Node で TypeScript を直接実行する手間が無く、CI の `npm test` にそのまま乗る
- 検証ロジック本体は `logic/validate.ts` に置き、将来のエディタからも使えるようにした。チェック内容: id と参照、固定されていないパーツ、色ごとの本数、頭が面に乗っているか、軸が partIds に無いパーツを貫いていないか、ネジ同士の物理的な重なり、ソルバーで解けるか
- 「外せるか」判定は 2 段階のレイで行う。軸部分（先端→面、軸の半径）と頭部分（面→抜けきるまで、頭の半径）。隣り合う平行なネジを誤検出しないため
- `normalizeStage` は three.js に依存しない `logic/normalize.ts` に分け、ホーム画面が three.js を読み込まないようにした（メインチャンク約 280KB、ネジはずしの遅延チャンク約 970KB）
- 自動テスト用に、URL に `?nejidebug=1` を付けると `window.__nejiDebug` に残っているネジの画面座標と `tap(id)` が公開される
- ステージ一覧は難易度順（はこ → きのこ → くるま → ピンのとう → ゆきだるま → ロボット → タワー → ほんだな → ロケット → おしろ）
- 実機（iPad / iPhone）での操作感・性能確認は未実施（フェーズ 3 の残り）
- PWA は vite-plugin-pwa（injectManifest）+ Workbox に移行した。`src/sw.ts` が Service Worker 本体、`src/services/pwaUpdateService.ts` が更新検知（起動時・前面復帰時・1 時間ごと）とホーム画面での自動適用を担当。旧手書き SW のキャッシュ（`sagashimono-v1` / `asobihiroba-v2`）は新 SW の activate 時に削除される
