# マジックメイクミラー 開発ガイド

インカメラに映した顔を指でなぞってメイクを塗ったり（顔認識の 478 点をもとに、塗った所が顔に付いてくる）、どこにどう塗るかを矢印で案内したりする「かしこい鏡」の内部構造メモ。
計画と未決事項は `docs/お化粧アプリ計画.md`、あそびひろば全体のルールは `CLAUDE.md` を見る。

## 1. 全体像

```
MakeupApp（画面の切り替え・カメラ / 写真・設定と最後の色の保存）
 ├─ IntroScreen   はじめに: 説明 → 「カメラを つかう」 / 「しゃしんで ためす」
 └─ MirrorScreen  ミラー画面
      ├─ StageView      <video>（鏡像）または <img>。重ねる canvas の置き場
      │    ├─ MakeupCanvas → makeupRenderer  メイクの描画（WebGL。映像ごと描いて合成）
      │    ├─ GuideCanvas                    おしえて の領域・矢印・目印、ためす の「ここに ぬれるよ」の点線、デバッグの点群
      │    ├─ PaintSurface                   ためす のときだけ重ねる透明な面。指でなぞった位置を塗りに変える
      │    └─ 状態欄 / 読み込みの進捗 / はやさ
      ├─ TryPanel（パレット）/ GuidePanel / SuggestPanel  操作パネル（モードタブで切り替え）
      └─ SettingsSheet  せってい
```

- **ためす は「なぞって塗る」**。パレットで色を選んだだけでは顔に付かず、映像の顔を指でなぞった所に付く。塗った絵は `components/facePaint.ts`（`FacePaint`）がレイヤーごとの canvas で持ち、React の state にはしない（なぞるたびに再描画しないため）
- 顔認識は `hooks/useFaceTracker.ts` が回す。最新の結果は `frameRef`（React の再描画なし）に入り、描画 canvas は `subscribe` か自前の rAF で読む。状態欄の文言や FPS だけが React の state。フックの戻り値は状態が変わるたびに新しくなるので、effect の依存には中の `frameRef` / `subscribe`（変わらない）を使う
- プラットフォーム（あそびひろば）に依存するのは `MakeupApp` の props（`onExit`、`storageKey`）と共通フック（`useTapGuard`）だけ。単体アプリに切り出すときは `src/games/makeup/` と `public/makeup/` をコピーする

## 2. データの流れ

```
<video> / <img>
   │ 映像のコマが変わるたび（推論のあとは、かかった時間の半分だけ休む）
   ▼
services/faceTracker.ts   MediaPipe Face Landmarker（VIDEO モード）→ 478 点 + blendshapes
   │ 近いときは、余白を足した絵で認識して座標を戻す（logic/closeRange.ts）
   ▼
logic/smoothing.ts        指数移動平均（0.5）／ 見つからなくても 0.5 秒は直前の結果を使う
   ▼
FaceFrame（frameRef）──┬─ logic/pose.ts → 状態（かおなし / とおい / ちかい / よこむき / くらい / OK）
                       ├─ logic/faceMesh.ts（三角形の網 + UV）
                       │     ├─ PaintSurface: 指の位置 → 顔のどこか（UV）→ FacePaint にスタンプ
                       │     └─ makeupRenderer: FacePaint の絵（UV）を、今の顔の点の位置に貼って合成
                       ├─ logic/regions.ts → 唇・目・まぶた・眉・頬・ハイライトの形、名前付きの点と線
                       │     ├─ FacePaint.mask（パーツの型。はみださない / 自動で塗る）
                       │     ├─ logic/guide.ts（ステップ → 領域・矢印・目印）→ GuideCanvas
                       │     └─ logic/suggest.ts（比率 → 顔型・目型・大きさ）→ SuggestPanel
                       ├─ hooks/useAutoPan → 枠からはみ出した映像のうち、顔のある側を見せる
                       └─ blendshapes → usePoseCheck（にっこり / 目を閉じる）
```

座標は 2 種類ある。

- **映像の座標**: 顔の点は正規化座標（0〜1）、領域は映像のピクセル（`frameSize`）。canvas の内部サイズを映像に合わせ、CSS は video と同じ `object-fit: cover` ＋ 鏡像の `scaleX(-1)` を当てるので、重ねる canvas は変換を考えなくてよい
- **UV（塗る絵の座標）**: 顔を平らに開いた 1 枚の絵（0〜1）。顔が動いても・口を開けても・横を向いても、同じ肌の場所は同じ UV になる

画面の位置（タップ）→ 映像の座標 の変換は `logic/viewport.ts`（cover・鏡像・`useAutoPan` のずらしを考える）。

## 3. 顔認識（`services/faceTracker.ts` / `hooks/useFaceTracker.ts`）

- wasm は `@mediapipe/tasks-vision` の `exports`（`vision_wasm_internal.js` など）を Vite の `?url` で取り込む。SIMD の有無（`FilesetResolver.isSimdSupported`）で 1 組を選ぶ
- 進捗を出すため wasm 本体とモデル（`public/makeup/models/face_landmarker.task`）は自分で `fetch` し、wasm は Blob URL、モデルは `modelAssetBuffer` で渡す（同じファイルを二重に落とさない）。モジュール内に 1 回だけキャッシュする
- `delegate` は、iPhone / iPad では CPU、それ以外では GPU が既定（`services/gpuGuard.ts`）。実機（iPad、iOS 17、ホーム画面 PWA）で、GPU での最初の推論に入ったまま戻らず、15〜35 秒後にブラウザごと落ちることがデバッグログで分かったため（5 回中 5 回、「すいろん 1 かいめ: まえ」で記録が終わる）。推論は同期処理なので、固まるとあとから切り替えられない。設定で GPU を選び直せるが、GPU を作る前に印（`makeup_gpu_pending`）を残し、最初の推論が終わる前に落ちたら、次からは自動で CPU にする（`makeup_gpu_failed`）。GPU の作成に失敗したときも CPU で作り直す
- Service Worker（`src/sw.ts`）は `.wasm` / `.task` を `makeup-model` キャッシュに CacheFirst で入れる。初回はオンライン必須、2 回目からオフラインでも動く
- `detectForVideo` のタイムスタンプは単調増加が必要なので、同じ値が来たら +1 する
- 信頼度のしきい値は 0.3（`FACE_CONFIDENCE`。MediaPipe の既定は 0.5）。近づいて顔の一部が切れても追い続けるため

### 操作が詰まらないようにする

推論（`detectForVideo`）は同期処理で、その間は画面の操作が止まる。

- 映像のコマ（`video.currentTime`）が変わったときだけ推論する。120Hz の画面では rAF がカメラの 1 コマの間に何度も来るので、毎回推論すると無駄に詰まる
- 推論のあと、かかった時間 × `INFERENCE_REST_RATIO`（0.5）だけ次の推論を待つ。推論が遅い端末でも、パレットを触る時間が必ず空く
- 写真は動かないので `PHOTO_INFERENCE_INTERVAL_MS`（250ms）ごと

### 近づいたときの認識（`logic/closeRange.ts`）

画面をなぞるために近づくと、顔が映像いっぱい（または はみ出す）になり、顔を見つける処理が効かなくなる。

- 映像のまわりに黒い余白を足した絵（映像は真ん中に 1/1.5 の大きさ）を渡して認識し、点を元の映像の座標に戻す（`unpadLandmarks`。映像の外にはみ出した点は 0〜1 の外になる）
- 実測（サンプルの顔写真を拡大。ヘッドレス Chromium）: そのままだと顔の幅が映像の短い辺の約 1.5 倍で見失うのが、余白つき ＋ しきい値 0.3 で約 2 倍まで追える
- 余白つきは顔が小さく写るぶん精度が少し落ちるので、ふつうの距離では使わない。顔の幅が短い辺の 0.7 倍を超えるか、顔が映像の縁にかかったら切り替え、0.5 倍より小さくなったら戻す。見つからないときは 0.7 秒ごとに入れ替えて探す
- カメラは 4:3（960×720）で頼む（`services/camera.ts`）。インカメラのセンサーは 4:3 なので、16:9 より上下が広く写り、近づいても顔が枠から出にくい
- `hooks/useAutoPan.ts`: 映像は枠いっぱいに広げて表示するので、枠と映像の形が違うと端が切れる。切れる側を顔に合わせてずらし（CSS 変数 `--mmm-pan-x` / `--mmm-pan-y` → `object-position`）、顔が画面に残るようにする
- 「すこし はなれてね」は、認識が切れる手前（顔の幅が短い辺の 1.6 倍）まで近づいたときだけ出す

## 4. なぞって塗る・メイクの描画

### 顔メッシュと UV（`logic/faceMesh.ts`、データは `logic/meshData.ts`）

- 三角形 852 枚（MediaPipe の `FACE_LANDMARKS_TESSELATION`）と、点ごとの UV（MediaPipe の標準の顔モデルのもの）。`meshData.ts` は `scripts/makeup/gen-mesh.mjs` が書き出す（モデルを入れ替えない限り作り直さない）
- 目の中と口の中には三角形が無いので、白目や歯には色が乗らない
- `locateOnFace(landmarks, x, y)`: 映像の上の点 → UV。三角形ごとに重心座標で判定し、裏返った三角形（横を向いたときの向こう側）は捨てる。顔の外は `null`
- `projectFromFace(landmarks, uv)`: その逆（テストと自動操作用）

### 塗った絵（`components/facePaint.ts`）

- レイヤー（パーツ）ごとに 512×512 の canvas を 1 枚。色つきで塗るので、同じパーツに違う色を重ねられる（アイシャドウのグラデーションなど）
- `stroke(layer, stamps, brush, color, assist)`: 筆先（ぼけた円）のスタンプを UV の位置に押す。`assist`（はみださない）のときはパーツの型で切り抜く。`layer = null` は けしゴム（すべてのレイヤーから消す）
- `fill(layer, color)` / `fillLook(look)`: パーツの型どおりに自動で塗る（できあがりを みる / この いろで ためす）
- `mask(layer)`: パーツの型（UV）。「お手本の顔」（`logic/referenceFace.ts`。サンプルの顔の点）の上で `regions.ts` の形を描いてぼかし、顔メッシュを通して UV へ写す（`logic/maskWarp.ts` の `warpAlphaToUV`）。映像で見たときの大きさ・ぼかしで形を決められる。レイヤーごとに 1 回だけ作る
- 筆（`logic/brush.ts`）: パーツごとの太さと硬さ（チークは大きくふんわり、アイラインは細くくっきり）× ふとさ 3 段階。大きさは UV で持つので「顔に対する太さ」は顔の映り方によらない。「はみださない」のときは型が形を決めるので太めにする
- `snapshot()` / `restore()`: できあがりを みる の前に取っておき、もとに もどす で戻す
- 塗った絵は保存しない（開くたびに すっぴんから）。覚えるのは最後に選んだ色とつよさだけ（`makeup_last_look`）

### レイヤー（`logic/layers.ts`）

- `LAYER_ORDER`（下から）: base → concealer → blush → eyeshadow → eyeliner → brow → highlight → lip
- `LAYER_SPEC`: 合成モード（multiply / screen / normal）、型のぼかし（顔の幅に対する割合）、既定のつよさ、`tint`（multiply のあとに普通合成で足す割合。発色を補う）、`maxAlpha`
- `LookState` は「パーツごとに選んでいる色と つよさ」。つよさ はレイヤー全体の濃さで、塗ったあとからも変えられる
- `LAYER_REGIONS`: パーツごとの「ここに ぬれるよ」の点線に使う領域の名前

### 描画（`components/makeupRenderer.ts`、WebGL）

1. 映像を canvas いっぱいに描く（**映像そのもの** を描く。`<video>` の上の要素に `mix-blend-mode` を使わないのは、iOS で効かないことがあるため）
2. 塗ってあるレイヤーごとに、顔メッシュを今の顔の点の位置に置き、塗った絵（UV）をテクスチャとして貼って合成する。乗算・スクリーン・普通は `blendFuncSeparate` で行う。裏返った三角形はカリングで描かない
3. 顔の輪郭は点がぶれやすいので、輪郭に近づくほど薄くなる絵（`edgeFeatherUV`）を掛けてなじませる
4. 塗ったものが無いときは canvas を透明にして、下の `<video>` を見せる
- 描き直すのは「映像のコマ・顔の点・塗った絵・つよさ」のどれかが変わったときだけ
- 保存（`MakeupView.capture`）: WebGL の canvas は描いた直後でないと読めないので、描き直してから新しい canvas に写す → JPEG → 共有シート / ダウンロード（`services/share.ts`）

### メモリ（iPad で落ちた原因と対策）

以前は Canvas 2D で、顔の点が来るたびにレイヤーごとの「ぼかしたマスク」を作り直していた。Safari は canvas の `filter` が使えず、代わりのぼかしが **毎フレーム・レイヤーごとに新しい canvas を 2 枚** 作っていたため、色を選んだ瞬間からメモリが尽きて落ちた（選んだ色は保存されるので、次からは開いた直後に落ちた）。

- canvas・テクスチャ・バッファは最初に 1 回だけ作り、使い回す。毎フレーム `document.createElement('canvas')` しない
- ぼかしは canvas の `filter` に頼らず、配列の上で行う（`blurAlpha`）。どのブラウザでも同じ結果になる
- 選んだ写真は長い辺 1280px までに縮めてから使う（`services/photo.ts`。写真の実サイズが、そのまま描画の canvas とテクスチャの大きさになるため）
- 使い終わった canvas は `width = 0` でメモリをすぐ返す。画面を離れるときは WebGL のコンテキストも手放す（`WEBGL_lose_context`）
- `makeup-face` の e2e が、`filter` を消した状態で「描画中の 3 秒間に canvas を 1 枚も作らない」ことを確かめる

### 画面の並べ方

映像がいつも画面の真ん中に来るようにする（`makeup.css`）。

- 横向き（幅 700px 以上）: 操作パネルを 2 つに分け、映像の左（`.mmm-panel-a`: モード・パーツ・ふとさ・つよさ・写真のボタン）と右（`.mmm-panel-b`: 色・ボタン・ひとこと。おしえて / ていあん の中身）に置く。`.mmm-panels` を `display: contents` にして、`order` で 左パネル → 映像 → 右パネル の順に並べている
- 縦向き: 映像の下に、2 つの部分を続けて並べる（`.mmm-panel` を `display: contents` にして 1 列にし、写真のボタンは `order` でいちばん下へ）。高さは画面の 52% までで、あふれたら中でスクロールする
- `TryPanel` は `section="tools"` / `section="colors"` で 2 か所に分けて描く

### 落ちたときの調べ方（デバッグログと切り分けスイッチ）

実機ではブラウザごと落ちると何も残らないので、要所ごとに記録（足あと）を端末へ残している。

- `services/diagnostics.ts` の `diag(message, data, replaceKey?)` を呼ぶ。保存はあそびひろば側（`src/services/debugLogService.ts`）で、`MakeupApp` の `onDebugLog` で受け取る。localStorage へその場で書くので、落ちたあとに開き直しても読める
- 記録している所: 画面の切り替え、設定、カメラ（頼んだ条件・実際の大きさ・失敗）、顔認識の読み込み（wasm / モデルを受け取った・作る前・できた・失敗）、**最初の 3 回の推論の前後**、近いとき用の切り替え、描画（作る前・できた・最初の 1 枚の前後・WebGL が失われた / 戻った）、型を作った時間、塗る絵を作った、なぞり始め、5 秒ごとの状態（1 行を上書き。経過秒・推論回数・推論時間・顔の状態）
- 「まえ」で記録が終わっていたら、その処理の中で落ちている。「じょうたい」が最後なら、動いている途中で落ちている（経過秒と推論回数で、どのくらい動いたかが分かる）
- 見る場所: ホーム画面下の「🐞 デバッグ」、はじめに / ミラー画面の ⚙️ →「デバッグの きろくを みる」。「☁️ リポジトリに ほぞん」でリポジトリの `debug-logs` ブランチに保存でき（落ちたあとの起動では、GitHub のトークンがあれば自動）、コピー / おくる でも文字として取り出せる。前の回がミラー画面の途中で終わっていたら、はじめに に案内が出る
- 切り分けスイッチ（⚙️ の「しらべる」。はじめに からも開ける）: 「かおを みつけない」（顔認識を止める）/「メイクを かかない」（WebGL の描画を止める）/「カメラを ちいさく する」（640×480）、と従来の GPU / CPU。どれを切ると落ちなくなるかで原因を絞る
- 映像・顔の点そのものは記録しない（大きさ・時間・件数などの数字だけ）

## 5. おしえて（手順ガイド）

- レシピは `public/makeup/recipes/<id>.json`、一覧は `recipes/index.json`。形式は `README.md` の「レシピ JSON フォーマット」
- `logic/guide.ts` の `buildGuideDrawing(step, regions)` が、名前で書かれた領域・線・点を今の顔の形に解決する。`GuideCanvas` は自前の rAF で毎フレーム描く（領域は明滅する薄い塗り ＋ 流れる点線、矢印は線に沿って 1.5 秒周期で流れる光と矢じり）
- `pose: 'smile' | 'closeEyes'` のステップは `usePoseCheck` が blendshapes で判定し、パネルの文言を切り替える（チークは「にっこりした頬の高い所」が正しい位置なので、笑顔のときの点で領域を出す）
- 「できあがりを みる」はレシピの `look` を、パーツの型どおりに自動で塗る（`recipeLook` → `FacePaint.fillLook`）。「もとに もどす」で、塗ってあったものに戻す
- `logic/validateRecipe.ts` が参照切れを検出する。`src/games/makeup/recipes.test.ts` が全レシピを検証し、サンプルの顔で全ステップの描くものが作れることを確かめる（`npm test`）

## 6. ていあん（`logic/suggest.ts`）

| 判定 | 計算 | 分類 |
|---|---|---|
| 顔のかたち | 縦（10→152）/ 頬幅（234→454）、あご幅（172→397）/ 頬幅、額幅（54→284）/ 頬幅 | おもなが（縦横比 ≥ 1.42）/ しかく（あご ≥ 0.86）/ ハート（額 − あご ≥ 0.14 かつ あご < 0.78）/ まる（縦横比 < 1.22）/ たまご |
| めの かたち | 目尻の上がり（(目頭.y − 目尻.y) / 目の幅、左右の平均で頭の傾きを打ち消す） | つりめ（≥ 0.09）/ たれめ（≤ −0.03）/ ふつう |
| めの おおきさ | 目の幅 / 頬幅 | おおきめ（≥ 0.215）/ ちいさめ（≤ 0.175）/ ふつう |
| はだ | 「しんだん する」を押した瞬間に両頬の小領域の平均色（`components/skinSample.ts`） | 明るさ（輝度 175 / 115）、色み（(R − B) / 輝度 が 0.42 以上で あたたかい、0.28 以下で すずしい） |

閾値は `THRESHOLDS` にまとめてあり、サンプルの顔（`logic/fixtures/portrait-frame.json`）が「たまご・ふつう・ふつう」になるように決めてある。精度は「めやす」で、画面にもそう書いている。

## 7. 内容データの増やし方

- **色を増やす**: `public/makeup/palettes.json` に `{ "name", "color" }` を足す（色は `#rrggbb`）
- **手順を増やす**: `public/makeup/recipes/` に JSON を足し、`index.json` に 1 行足す。領域・線・点は `regions.ts` の `REGION_NAMES` / `PATH_NAMES` / `POINT_NAMES` にある名前だけ使える。`npm test` で参照切れとステップ数の不一致が見つかる
- **新しい領域や点**: `regions.ts` に番号を足し、`FaceRegions` と `regionShape` / `points` に追加する。番号は設定の「かおの てんを みせる」＋ `?makeupdebug=1`（番号つき）で確かめる
- **新しいレイヤー**: `layers.ts` の `LayerId` / `LAYER_ORDER` / `LAYER_SPEC` / `shapesForLayer` / `LAYER_REGIONS`、`brush.ts` の `BASE_BRUSH`、`palettes.json`、`strings.ts` の `parts`、`constants.ts` の `PART_EMOJI`

## 9. 動作確認

```bash
npm test                               # 平滑化・向き・領域・レイヤー・顔メッシュ・型の写し・筆・近距離・画面の変換・レシピ・ていあん の単体テスト
bash scripts/e2e/run.sh makeup-smoke   # 偽カメラで はじめに → ミラー → もどる（カメラが止まるか）
bash scripts/e2e/run.sh makeup-face    # 顔写真で 478 点 → なぞって塗る（鏡像・近づいた映像・はみださない・じゆう・けしゴム・ほぞん）→ おしえて → ていあん
bash scripts/e2e/run.sh offline        # 一度開いてから切っても顔認識が動くか（他のゲームも）
```

- `?makeupdebug=1` で `window.__makeupDebug`（最新の点群・状態・FPS・look・塗ってあるパーツ `painted`・ガイドのステップ・しんだん結果、`applyLook(look)`、顔の点の画面上の位置 `facePoint(番号)`、その位置に見えている色 `pixelAt(x, y)`）が公開される
- `makeup-face` は、顔の点の位置を実際にドラッグして塗り、内部の絵とスクリーンショットの両方で「なぞった所にだけ色が付いたか」を確かめる
- テスト用の顔写真は `makeup-face.cjs` が MediaPipe のサンプル画像をダウンロードし、ffmpeg で y4m にして偽カメラに流す（`scripts/e2e/assets/`、git 管理外）。点群は `logic/fixtures/portrait-frame.json` に入れてあり、`E2E_WRITE_FIXTURE=1` で書き直せる
- ヘッドレス Chromium（SwiftShader）では推論が 150ms〜2 秒と遅い。実機の数字は設定の「はやさを みせる」で見る（近いとき用の認識に切り替わっている間は「ちかい」と出る）

## 10. 既知の制限・改良候補

- なぞって塗る・近距離の認識・WebGL の描画は、実機（iPad / iPhone）ではまだ確認していない（ヘッドレス Chromium の e2e のみ）。推論が重ければ `INFERENCE_REST_RATIO`、CPU 切替で調整する
- 塗れるのは顔メッシュの中だけ（髪・耳・首、額の生え際の近くは塗れない）。メッシュは額の上の方までしか無い
- 顔の幅が映像の短い辺の約 2 倍を超えるほど近づくと認識が切れる。広角のインカメラでズームを引く（`zoom` の制約）のは未対応
- 奥行きの判定はしていない。顔を大きく横に向けると、鼻と向こう側の頬の三角形が重なり、その帯だけ塗りが濃く見えることがある（裏返った三角形は描かないが、表どうしの重なりは残る。深度バッファを使うのが改良候補）
- 「もどす（1 つ前に戻す）」は無い。けしゴム と ぜんぶ けす で直す
- 塗った絵は保存しない（開くたびに すっぴん）
- iOS のホーム画面 PWA ではカメラ許可が保持されず毎回聞かれることがある（WebKit の既知問題）。Safari のタブで開けばサイトごとに許可を保持できる
- 手やブラシで顔の一部が隠れると点が揺れる。0.5 秒の保持と平滑化で抑えているが、隠れた側の形は崩れる
- メイクは色の合成だけで、ツヤ・ラメなどの質感は無い（シェーダーで光沢を足すのが候補）
- おしえて は実物の化粧の案内で、塗れたかどうかの判定はしない（ユーザーが「つぎへ」を押す）。おしえて の最中は画面をなぞっても塗れない
- ていあん の肌の色みは照明に強く左右される。白い紙を映して補正する、などが改良候補
- 単体アプリ化するときは `strings.ts` を大人向けの文言に差し替え、カメラ許可の保持が必要なら Capacitor などで包む
