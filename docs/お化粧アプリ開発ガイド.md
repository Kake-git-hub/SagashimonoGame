# マジックメイクミラー 開発ガイド

インカメラに映した顔の上に、顔認識（478 点）をもとにメイクを重ねたり、どこにどう塗るかを矢印で案内したりする「かしこい鏡」の内部構造メモ。
計画と未決事項は `docs/お化粧アプリ計画.md`、あそびひろば全体のルールは `CLAUDE.md` を見る。

## 1. 全体像

```
MakeupApp（画面の切り替え・カメラ / 写真・設定と最後の色の保存）
 ├─ IntroScreen   はじめに: 説明 → 「カメラを つかう」 / 「しゃしんで ためす」
 └─ MirrorScreen  ミラー画面
      ├─ StageView      <video>（鏡像）または <img>。重ねる canvas の置き場
      │    ├─ MakeupCanvas → makeupPainter  ためす の描画（映像ごと描いて合成）
      │    ├─ GuideCanvas                   おしえて の領域・矢印・目印、デバッグの点群
      │    └─ 状態欄 / 読み込みの進捗 / はやさ
      ├─ TryPanel / GuidePanel / SuggestPanel  下部の操作パネル（モードタブで切り替え）
      └─ SettingsSheet  せってい
```

- 顔認識は `hooks/useFaceTracker.ts` が回す。最新の結果は `frameRef`（React の再描画なし）に入り、描画 canvas は `subscribe` か自前の rAF で読む。状態欄の文言や FPS だけが React の state
- プラットフォーム（あそびひろば）に依存するのは `MakeupApp` の props（`onExit`、`storageKey`）と共通フック（`useTapGuard`）だけ。単体アプリに切り出すときは `src/games/makeup/` と `public/makeup/` をコピーする

## 2. データの流れ

```
<video> / <img>
   │ 毎フレーム（推論が 50ms を超えたら 2 フレームに 1 回）
   ▼
services/faceTracker.ts   MediaPipe Face Landmarker（VIDEO モード）→ 478 点 + blendshapes
   ▼
logic/smoothing.ts        指数移動平均（0.5）／ 見つからなくても 0.5 秒は直前の結果を使う
   ▼
FaceFrame（frameRef）──┬─ logic/pose.ts → 状態（かおなし / とおい / ちかい / よこむき / くらい / OK）
                       ├─ logic/regions.ts → 唇・目・まぶた・眉・頬・ハイライトの形、名前付きの点と線
                       │     ├─ logic/layers.ts（レイヤーの状態）→ makeupPainter（マスク → 合成）
                       │     ├─ logic/guide.ts（ステップ → 領域・矢印・目印）→ GuideCanvas
                       │     └─ logic/suggest.ts（比率 → 顔型・目型・大きさ）→ SuggestPanel
                       └─ blendshapes → usePoseCheck（にっこり / 目を閉じる）
```

座標はすべて **映像のピクセル**（`frameSize`）。canvas の内部サイズを映像に合わせ、CSS は video と同じ `object-fit: cover` ＋ 鏡像の `scaleX(-1)` を当てるので、変換を考えずに重なる。

## 3. 顔認識（`services/faceTracker.ts`）

- wasm は `@mediapipe/tasks-vision` の `exports`（`vision_wasm_internal.js` など）を Vite の `?url` で取り込む。SIMD の有無（`FilesetResolver.isSimdSupported`）で 1 組を選ぶ
- 進捗を出すため wasm 本体とモデル（`public/makeup/models/face_landmarker.task`）は自分で `fetch` し、wasm は Blob URL、モデルは `modelAssetBuffer` で渡す（同じファイルを二重に落とさない）。モジュール内に 1 回だけキャッシュする
- `delegate` は GPU 既定。作成に失敗したら CPU で作り直す。設定で CPU に固定もできる
- Service Worker（`src/sw.ts`）は `.wasm` / `.task` を `makeup-model` キャッシュに CacheFirst で入れる。初回はオンライン必須、2 回目からオフラインでも動く
- `detectForVideo` のタイムスタンプは単調増加が必要なので、同じ値が来たら +1 する

## 4. 領域とメイクの描画

### 領域（`logic/regions.ts`）

- `IDX`: 輪郭をなぞる順に並べた点の番号。`NAMED`: ガイドの目印に使う点。番号を書くのはこのファイルだけ
- `faceRegions(landmarks, w, h)` が 1 フレーム分の形をまとめて返す。多角形（唇・目・眉・まぶたの帯・目の下・輪郭）、楕円（チーク・頬骨・あご・額のハイライト）、太さの変わる線（アイライン。目尻側が太く、先に跳ね上げ）
- 左右は自分から見た左右。`R` = 番号の若い方 = 映像の左側 = 鏡像では画面の右側
- `shadowR/L` は上まぶたの際と眉のすぐ下の列で囲んだ帯。`underEyeR/L` は下まぶたの際と頬の上の列

### レイヤー（`logic/layers.ts`）

- `LAYER_ORDER`（下から）: base → concealer → blush → eyeshadow → eyeliner → brow → highlight → lip
- `LAYER_SPEC`: 合成モード（multiply / screen / normal）、ぼかし（顔の幅に対する割合）、既定のつよさ、`tint`（multiply のあとに普通合成で足す割合。発色を補う）、`maxAlpha`
- `lookReducer`: 色を選ぶ / つよさを変える / 消す / 全部消す / 置き換える。保存は `sanitizeLook` を通す

### 描画（`components/makeupPainter.ts`）

1. 顔の点が来るたびに、使っているレイヤーごとに「ぼかした色のマスク」を映像の半分の解像度で作り直す（`ctx.filter` の blur が使えなければ縮小 → 拡大で近似）
2. 毎フレーム、出力 canvas に **映像そのもの** を描いてから、マスクを `globalCompositeOperation` と `globalAlpha` で重ねる。メイクが無いときは canvas を透明にして下の `<video>` を見せる
   - `<video>` の上の要素に `mix-blend-mode` を使わないのは、iOS で効かないことがあるため
3. 保存（`capture`）は出力 canvas（メイクが無ければ映像）を鏡像のまま新しい canvas に写す → JPEG → 共有シート / ダウンロード（`services/share.ts`）

## 5. おしえて（手順ガイド）

- レシピは `public/makeup/recipes/<id>.json`、一覧は `recipes/index.json`。形式は `README.md` の「レシピ JSON フォーマット」
- `logic/guide.ts` の `buildGuideDrawing(step, regions)` が、名前で書かれた領域・線・点を今の顔の形に解決する。`GuideCanvas` は自前の rAF で毎フレーム描く（領域は明滅する薄い塗り ＋ 流れる点線、矢印は線に沿って 1.5 秒周期で流れる光と矢じり）
- `pose: 'smile' | 'closeEyes'` のステップは `usePoseCheck` が blendshapes で判定し、パネルの文言を切り替える（チークは「にっこりした頬の高い所」が正しい位置なので、笑顔のときの点で領域を出す）
- 「できあがりを みる」はレシピの `look` を ためす のレイヤーに流し込む（`recipeLook`）。「もとに もどす」で直前の色に戻す
- `logic/validateRecipe.ts` が参照切れを検出する。`src/games/makeup/recipes.test.ts` が全レシピを検証し、サンプルの顔で全ステップの描くものが作れることを確かめる（`npm test`）

## 6. ていあん（`logic/suggest.ts`）

| 判定 | 計算 | 分類 |
|---|---|---|
| 顔のかたち | 縦（10→152）/ 頬幅（234→454）、あご幅（172→397）/ 頬幅、額幅（54→284）/ 頬幅 | おもなが（縦横比 ≥ 1.42）/ しかく（あご ≥ 0.86）/ ハート（額 − あご ≥ 0.14 かつ あご < 0.78）/ まる（縦横比 < 1.22）/ たまご |
| めの かたち | 目尻の上がり（(目頭.y − 目尻.y) / 目の幅、左右の平均で頭の傾きを打ち消す） | つりめ（≥ 0.09）/ たれめ（≤ −0.03）/ ふつう |
| めの おおきさ | 目の幅 / 頬幅 | おおきめ（≥ 0.215）/ ちいさめ（≤ 0.175）/ ふつう |
| はだ | 「しんだん する」を押した瞬間に両頬の小領域の平均色（`components/skinSample.ts`） | 明るさ（輝度 175 / 115）、色み（(R − B) / 輝度 が 0.42 以上で あたたかい、0.28 以下で すずしい） |

閾値は `THRESHOLDS` にまとめてあり、サンプルの顔（`logic/fixtures/portrait-frame.json`）が「たまご・ふつう・ふつう」になるように決めてある。精度は「めやす」で、画面にもそう書いている。

## 7. 内容データの増やし方

- **色を増やす**: `public/makeup/palettes.json` に `{ "name", "color" }` を足す（色は `#rrggbb`）
- **手順を増やす**: `public/makeup/recipes/` に JSON を足し、`index.json` に 1 行足す。領域・線・点は `regions.ts` の `REGION_NAMES` / `PATH_NAMES` / `POINT_NAMES` にある名前だけ使える。`npm test` で参照切れとステップ数の不一致が見つかる
- **新しい領域や点**: `regions.ts` に番号を足し、`FaceRegions` と `regionShape` / `points` に追加する。番号は設定の「かおの てんを みせる」＋ `?makeupdebug=1`（番号つき）で確かめる
- **新しいレイヤー**: `layers.ts` の `LayerId` / `LAYER_ORDER` / `LAYER_SPEC` / `shapesForLayer`、`palettes.json`、`strings.ts` の `parts`、`constants.ts` の `PART_EMOJI`

## 8. 調整しやすい値

| 値 | 場所 | 意味 |
|---|---|---|
| `STATUS_THRESHOLDS` | `constants.ts` | とおい / ちかい（短い辺に対する顔の幅）、よこむき（度）、くらい（輝度）、直前の結果を保持する時間 |
| `SMOOTHING_ALPHA` | `constants.ts` | 点の平滑化。大きいほど追従が速く、ブレが残る |
| `SLOW_INFERENCE_MS` | `constants.ts` | これを超えたらフレームを間引く |
| `LAYER_SPEC` | `logic/layers.ts` | レイヤーごとのぼかし・合成・つよさ |
| `cheekEllipse` などの係数 | `logic/regions.ts` | チーク・ハイライト・アイラインの大きさ（顔の幅に対する割合） |
| `THRESHOLDS` | `logic/suggest.ts` | ていあん の分類の閾値 |
| `ARROW_PERIOD_MS` | `components/GuideCanvas.tsx` | 矢印が流れる周期 |
| `MASK_SCALE` | `components/makeupPainter.ts` | マスクの解像度（映像に対する割合） |

## 9. 動作確認

```bash
npm test                               # 平滑化・向き・領域・レイヤー・レシピ・ていあん の単体テスト（サンプルの顔のフィクスチャを使う）
bash scripts/e2e/run.sh makeup-smoke   # 偽カメラで はじめに → ミラー → もどる（カメラが止まるか）
bash scripts/e2e/run.sh makeup-face    # 顔写真で 478 点 → ためす（6 レイヤー・ほぞん）→ おしえて（ナチュラル）→ ていあん
bash scripts/e2e/run.sh offline        # 一度開いてから切っても顔認識が動くか（他のゲームも）
```

- `?makeupdebug=1` で `window.__makeupDebug`（最新の点群・状態・FPS・look・ガイドのステップ・しんだん結果、`applyLook(look)`）が公開される
- テスト用の顔写真は `makeup-face.cjs` が MediaPipe のサンプル画像をダウンロードし、ffmpeg で y4m にして偽カメラに流す（`scripts/e2e/assets/`、git 管理外）。点群は `logic/fixtures/portrait-frame.json` に入れてあり、`E2E_WRITE_FIXTURE=1` で書き直せる
- ヘッドレス Chromium（SwiftShader）では推論が 150〜200ms と遅い。実機の数字は設定の「はやさを みせる」で見る

## 10. 既知の制限・改良候補

- 実機（iPad / iPhone）での性能・操作感はまだ確認していない。推論が重ければ `SLOW_INFERENCE_MS` の間引き、`MASK_SCALE`、CPU 切替で調整する
- iOS のホーム画面 PWA ではカメラ許可が保持されず毎回聞かれることがある（WebKit の既知問題）。Safari のタブで開けばサイトごとに許可を保持できる
- 手やブラシで顔の一部が隠れると点が揺れる。0.5 秒の保持と平滑化で抑えているが、隠れた側の形は崩れる
- メイクの描画は Canvas 2D のベタ塗り ＋ ぼかし。ツヤ・ラメなどの質感は無い（three.js で顔メッシュにテクスチャを貼る方式が候補）
- 塗れたかどうかの判定はしない（ユーザーが「つぎへ」を押す）
- ていあん の肌の色みは照明に強く左右される。白い紙を映して補正する、などが改良候補
- 写真モードは VIDEO モードのまま同じ画像を毎フレーム渡している（1 枚だけ検出して止める方が省電力）
- 単体アプリ化するときは `strings.ts` を大人向けの文言に差し替え、カメラ許可の保持が必要なら Capacitor などで包む
